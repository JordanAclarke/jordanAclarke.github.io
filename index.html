How I build agents

Five principles of reliable agents, and how I apply them

  1. Keep the model’s job small. The model chooses the action; deterministic code carries it out. How I apply it: the assistant’s tools are services that call REST APIs, so code, not the model, performs every action.
  2. Design the tools as carefully as the prompt. Clear descriptions and well-defined inputs decide how reliably an agent behaves. How I apply it: I author the tool descriptions and schemas and keep them in sync with the API, and I limited the assistant to the actions each user is permitted to take.
  3. Keep humans in control of consequential actions. How I apply it: I led adoption of one approval experience across multiple tools and codebases.
  4. Ground the agent in a source of truth, with guardrails. How I apply it: the assistant’s actions and answers always match the official system of record.
  5. Make it observable, and test it before it ships. How I apply it: an automated test gate before anything ships, and LangSmith traces to diagnose problems.

Principles drawn from Anthropic, OpenAI, and 12-Factor Agents.

AI agent project

Work from my role at Workday.

Flagship project

A production AI assistant that acts on sensitive enterprise data

Employees submit and manage requests, such as time off and leave, through chat. The assistant takes only valid actions, asks for approval before any change, and stays consistent with the system of record.

Challenge
An assistant that changes enterprise records has to be correct, approved, and consistent with the official record. Every customer configures their system differently, and it has to work for each of them.
Approach
Tools and agent definitions that adapt one assistant to each customer’s configuration; APIs and guardrails that limit it to valid actions; a shared human approval step before changes; and automated tests before every release.
Source of truth
The system of record decides what is true. The assistant’s actions and answers are checked against it, and tests and tool descriptions are verified before every merge.
Outcome
Users complete real tasks in chat, and every action is valid, human-approved, and consistent with the official record.
